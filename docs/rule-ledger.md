# Rule ledger

This ledger lists every normative rule in the pipeline's charter (`skills/_shared/references/pipeline-constitution.md`),
the shared workflow contract (`skills/_shared/references/project-control.md`), every `skills/*/SKILL.md`, and the six
checker agents (`agents/*.md`). Each rule gets one row: what it says, its label, the failure it prevents, where it is
enforced, and the evidence that it matters. It lives in the repository only and is never loaded at run time.

It is the method for trimming skill text safely (plan section 6.2 and decision D5). Two standards shape it. pstack's
`/correct` fixes a repeated mistake at the highest level that works: architecture first, then types, then a lint or CI
check, then a test, and documentation last. The handbook's appendix B says a new hard requirement needs a named failure
it constrains, an implementation cost, and observable acceptance conditions, and that rules without a trigger, owner, or
test should be removed, supported with evidence, or downgraded.

## How to use it

- **pointer**: the rule's prose is fully enforced by a script, hook, or checker, so the prose shrinks to one line that
  names the enforcement.
- **dedupe**: the same rule is stated in several places. It keeps one home (named in the row); the other places become
  pointers or go.
- **propose-delete**: the rule names no failure and has no evidence. It is proposed to the owner for deletion. The owner
  decides every deletion; this ledger deletes nothing.
- **strengthen**: a Must rule held only by prose that a script could check. The row names the check, in `/correct`'s order.
- **keep**: the rule stays as written.

When a rule changes, its row changes in the same commit. A rule that guards against a failure in the README's list is
never proposed for deletion. Those failures carry a tag in the "Failure it prevents" column:
[imitation] drifting toward a familiar imitation of what was meant; [scope] quietly narrowing or widening scope;
[hidden] hiding failures behind fallbacks; [unwired] leaving built parts unwired; [early-done] calling things done too
early; [lost-decision] losing decisions across compaction, sessions, and tools.

## Conventions

- Line numbers (L21, L40-43) refer to the source file at commit 587f48c.
- Labels follow the handbook's chapter 1. **Must**: an engineering baseline for a stated risk, which needs control
  evidence. **Default**: a starting point, changed with a recorded reason and a comparison. **Conditional**: needed
  only for a named workload (a user interface, a venture project, Codex, the final milestone, an intent check).
- Script names without a folder live in `skills/_shared/scripts/`. Hooks are in `hooks/`. `milestone-continue.py` is
  `skills/dev/scripts/milestone-continue.py`. `static_checks.py` is `tests/static_checks.py`. `settings_patch.py` and
  `install.py` are at the repository root.
- Evidence names a test method in `tests/test_*.py`, a fixture key from `FIXTURES` in `tests/fixture_expectations.py`
  (run by `tests/agent_fixtures.py`), or a scenario in `tests/system_scenarios.py` (written "scenario <name>").
- "prose only" means no code checks the rule. "(unverified)" marks a claim that could not be confirmed from the code.
- The duplicate blocks D1 to D4 are defined in the summary at the end.
